在当前仓库排查「booster 定时任务关闭后仍在自动刷量」问题。当前目录应是生产机上 pyappify 拉取的应用数据目录（含 app.py）。

## 步骤

1. 运行 `python tools/diagnose_booster.py` 并完整读取输出。
   - 若 `tools/diagnose_booster.py` 不存在：说明生产代码没有更新到 v1.4.0，直接给出结论「更新未生效」，指导用户在 pyappify 中重新更新并重启应用后重试，无需继续。
2. 按脚本输出逐节判读：
   - 第 1 节缺 v1.4.0 修复标记 → 更新未生效（旧代码存在停止竞态与孤儿进程两个缺陷）；
   - 第 2 节出现多个 app.py python 进程、或监听进程启动时间早于磁盘 app.py 修改时间 → 孤儿进程仍在运行（这是「关了还在刷」的最常见原因）；
   - 第 3 节 `running=true` → 定时实际开着；有新任务但 `running=false` → 按任务来源字段区分：`log_target=booster-schedule` 为定时来源（结合孤儿/版本判断），无该字段为手动或 webhook 来源；
   - webhook 监听开启 → 提醒用户检查推送来源。
3. 需要结束进程时**先向用户确认**（生产机可能跑着其它 python 程序），只结束 cmdline 指向本应用 app.py 的 python 进程；若普通权限杀不掉（对方是管理员启动），提示用户用管理员 PowerShell：`Stop-Process -Id <PID> -Force`，或直接重启电脑。
4. 处置后重跑脚本验证：只剩一个实例、定时关闭、无未结束任务。
5. 最后输出简明结论：根因、已采取措施、后续观察建议。若确认代码是 v1.4.0、全机仅一个进程、定时关闭，但仍有新任务产生，把完整脚本输出发回给开发者深查。
